# E62 G13B3 — paired, immutable regression binaries

This folder is an explicit **SIM_ONLY, known-status regression baseline**, not a
production firmware release. It contains a pinned ESCape32 Rel17.3 ARM ELF,
the QEMU 6.2.0-derived AM13E x86-64 executable, and the `libfdt.so.1` runtime
dependency from the same Ubuntu 24.04 provenance.

The executable files and `manifest.json` / `SHA256SUMS` are generated by
[`publish-e62-pinned-binaries.yml`](../../.github/workflows/publish-e62-pinned-binaries.yml)
**from source-keyed CI caches**. They must never be replaced by an arbitrary
local GCC/Clang build. Publication checks the **exact original CI fast-ramp
ELF SHA-256**, QEMU Machine implementation hashes, pinned upstream QEMU gitlink,
QEMU device-level history QTest and the **unchanged six-sector original Guest
native acceptance gate** before committing the binary files.

## Known status, not an all-PASS baseline

- G13B3L, original Guest six-sector controlled SIM_ONLY test: **PASS** in
  previous CI run [40107025185](https://github.com/cctsao1008/escape32-qemu/actions/runs/40107025185).
- G13B3M, original Guest 12-sector / 90 ms rotor-direction stability:
  **FAIL — rotor reversal** in the same run.
- Historical QEMU internal PWM events: observable; **no physical MOSFET,
  driver deadtime, current, thermal or flight qualification**.
- The host binary targets **Ubuntu 24.04 x86-64**. A different WSL/Linux
  distribution may have incompatible glibc or other SONAMEs; a hash match
  alone cannot establish host ABI compatibility.

The manifest describes the binary pair and its known failure. It does not
convert any native Strict Gate failure into PASS.

## Use on a supported Ubuntu 24.04 x86-64 host

```bash
cd ~/github/escape32-qemu
python3 tools/e62_pinned_baseline.py verify --smoke-qemu
export LD_LIBRARY_PATH="$PWD/baseline/e62-g13b3/qemu/linux-x86_64:${LD_LIBRARY_PATH:-}"
python3 tests/g13b3_pwm_history.py \
  --qemu "$PWD/baseline/e62-g13b3/qemu/linux-x86_64/qemu-system-arm" \
  --elf "$PWD/baseline/e62-g13b3/firmware/AM13E-rev17.3.elf"
```

To exercise the pinned original Guest instead of an ELF rebuilt by local
GCC 15.2, point `tests/g13b2_native_drive_probe.py` at these same
`--elf` / `--qemu` paths. Keep the original native command parameters,
factory Flash Cfg and all Strict Gates unchanged.

## Updating the baseline

Modify the upstream Guest or Machine source as needed, **build with the
controlled CI toolchain**, verify the same accepted version in CI, then
**explicitly publish an updated pair** and commit its new ELF, QEMU,
SHA256SUMS and manifest together. Changes to `build.sh`, the Machine
sources or the board fixtures invalidate the prior pairing and cause
`verify` to fail closed. The v1 publisher intentionally accepts only
the exact G13B3 fast-ramp Guest SHA from the prior verified CI run;
to publish a genuinely new Guest, review and change this expected digest
as part of a separately audited baseline update. Historical versions
remain accessible through Git commits; no implicit floating `latest`.

The repo's normal source-build CI still exists for independently checking
build reproducibility. Ordinary regression runs can use these pinned
binaries directly without compiling QEMU or ESCape32.

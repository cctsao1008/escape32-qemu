# E62 G17–G20 P0: original Guest BEMF timing and rotor stability

Scope: ECX87-KV147, original unmodified TI AM13E ESCape32 Rel17.3 ELF,
24V SIM_ONLY source-clocked native Guest PWM → current-continuous motor
→ model BEMF → QEMU CMPSS0 filtered comparator → ECAP1 CAP1 →
original Guest TIMG12 scheduled commutation → next Guest PWM.

**Firmware ELF identity**: SHA256
`05563b6931b58aaba1df5105313c36c9de2d5797a0a3b190c86777c5773f13c0`.

**Never confuse** a passed original Guest twelve-sector *logic path* with
passed physical/modeled rotor stability. The independent G20 Strict Gate
requires at least 12 original CAP1/TIMG12/PWM sectors, 90 ms, 600 powered
PWM samples, at least one powered post-sector WFI, and **zero** significant
modeled rotor direction reversals. Do not waive any criterion to get green.

## G17: actual sampled BEMF vs predicted BEMF

Run `tools/native_bemf_timing_audit.py` on the native WFI trace
(`artifacts/e62-g16-ecx87-wfi-history.json`). For each original WFI:

- Verify `e_phase = Ke_electrical * pole_pairs * omega_mech *
  sin(electrical_angle + phase_offset)` against the motor sample.
- Verify the actual SIM_ONLY ADC comparator words against explicit
  `Vref=3.3V, bias=1.65V, gain=0.02V/V`.
- Find bounded theoretical input-level transitions using **two real WFI
  samples** (bracketing an unknown physical crossing time).
- Associate accepted Guest CAP1 to the preceding phase/polarity crossing
  interval, allowing only one actually observed maximum WFI gap after
  BEMF injection for comparator/filter response.
- Distinguish phase-geometric zero from **motor mechanical speed crossing
  zero**. The latter creates a legitimate BEMF voltage zero even if
  the rotor has not passed its expected electrical-angle marker;
  a firmware comparator may accept an electrically valid but
  *commutation-invalid* zero under this simplified motor model.

These are sample-bracketed MODEL diagnostics, not analog oscilloscope
measurements or proof of a full high-speed sensorless startup.

## G18: original Guest CAP1 → TIMG12 → PWM

Trace contains real simulated ECAP1 CAP1 capture timestamps and Guest TIMG12
service timestamps. For each accepted sector, record:

- Source-code-defined comparator phase and edge polarity
- Native CAP1 time, TIMG12 service time, CAP1-to-TIMG12 delay in us
- Rotor model electrical angle interpolated between neighboring Guest WFI
  checkpoints, **not** a true atomic angle measured at the IRQ instant
- Model zero-crossing bracket and classification (speed sign / angle / both)
- Original six-step path checked independently by
  `tools/native_extended_run_gate.py`

Reference original-Guest CI [G16 G17/G18 source results](https://github.com/cctsao1008/escape32-qemu/actions/runs/40248165749):

- 1316 original WFI source samples, 12 real native CAP1/TIMG12 pairs,
  all correctly time-ordered.
- Modeled BEMF formula error max 1.4433e-14 V; analog input codes
  0 mismatches.
- Twelve expected phase/polarity zero-crossing intervals successfully
  bracketed to CAP1, with **240 ns after the second WFI sample** for
  each event in prior repeated run; this is a modeled digital filter/sampling
  observation, NOT measured analog comparator silicon delay.
- Actual CAP1→TIMG12 delay **1.894–2.667 ms** (12 sectors in latest run).
- Source WFI sign audit: **8/12 CAP1 are attributed to mechanical RPM
  sign changes without the selected phase's geometric rotor-angle zero**;
  4/12 are unresolved at WFI/ADC quantization resolution, and **0/12**
  are confirmed geometric-only crossing events. This is an independent
  diagnostic classification, not proof that physical hardware behaves
  the same way.
- The accepted comparator edges are genuinely generated from modeled
  BEMF; **a voltage zero due to rotor reversal is not a valid
  electrical-angle timing marker**. Do not confuse a correct captured
  edge with correct sensorless commutation.

## G19: evidence-bound QEMU comparator filter correction

Before correction, every individual QTest BEMF input write could unconditionally
cancel/restart a pending QEMU CMPSS digital majority-filter timer, even when
the selected comparator raw input had not changed. The Host originally
writes U/V/W individually per WFI. This is not legitimate raw analog
edge behavior. The correction in `machine/am13e_motor_feedback.inc`:

- Preserves an in-flight filter across exact no-op sample writes
  and updates to currently unselected phases.
- Evaluates/restarts only for a **selected comparator raw-output level
  transition**, for both individual QTest writes and atomic auto vectors.
- Still routes only original comparator → ECAP1 CAP1, never manually
  forces Guest CAP1, TIMG12, SRAM, motor speed or PWM.
- Native QEMU `tests/g10_feedback.py` regression:
  `PASS_G19_SELECTED_RAW_CHANGE_ONLY_FILTER_UNSELECTED_NOOP`.
- Pure C extraction regression is updated and passes separately.

This is a simulator timing-model fix, **not** evidence that the motor
will reverse in physical hardware, or that firmware timing is defective.

## G20: strict qualification, not green merely because G17–G19 ran

Reference source [G19-corrected ECX87 Native CI](https://github.com/cctsao1008/escape32-qemu/actions/runs/40248165749):

- Original firmware accepted 12 sectors in 107.820 ms, plus a powered
  endurance-tail WFI.
- Significant rotor direction reversals: **23**.
- Modeled peak phase current: roughly **181.6 A** (SIM_ONLY model output,
  not board-current measurement or silicon rating).
- First significant reversal after sixth sector at WFI #849;
  rotor electrical angle ~124.0 degrees versus original sector-1 stator
  torque vector at 0 degrees; instantaneous modeled electromagnetic
  torque ~-5.33 Nm.
- Independent Strict Gate: **FAIL**:
  `SIM_ONLY motor trajectory reversed or missing`.
- Model remains **uncalibrated**, with zero propeller load and idealized
  diode/current/analog models. Do not invent torque/load, change ESCape32
  firmware, silence reversals, or lower the strict gate to manufacture a pass.

A complete G20 acceptance is still **OPEN** until a genuinely stable,
physically grounded motor/coupling scenario passes the unchanged strict
gate. The phase-vs-speed crossing audit identifies a concrete **SIM_ONLY
feedback mechanism**: at least 8/12 accepted native CAP1 inputs represent
modeled speed reversals rather than geometric rotor zero-crossings.
The model already reverses when the firmware receives some captures;
altering the QEMU filter cannot correct its uncalibrated motor dynamics.
Motor-model parameter validation and real propeller/board data remain
needed before physical claims or attempting to qualify G20.
